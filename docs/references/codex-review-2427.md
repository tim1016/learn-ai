# Command targeting and receipt identity across fleet boundaries

Investigation: [[Codex] Command targeting and receipt identity across fleet boundaries](https://github.com/tim1016/learn-ai/issues/2427). Baseline: `10b5f31b529c8507bd19bb24015f3d85fa9aba43`. Report-only branch: `research/codex-2427-fleet`.

**Result: no new Critical/High.** One Medium display-identity finding. The examined coordinator/agent boundaries fail closed on stale identity and preserve uncertain command outcomes. This conclusion does not establish universal broker correctness or validate a deployed fleet.

## F1 — A delayed ordinary action receipt can appear under a changed bot context

**Claim.** The ordinary bot action captures the right command target, but adopts its asynchronous receipt without checking that the shell still displays that target.

**Goal.** Correctness; architecture.

**Severity. Medium.** This can mislead an operator about which displayed bot an action affected. The actual command remains directed to its original account/bot; the durable receipt remains authoritative and recoverable. No wrong order or cross-account execution was demonstrated.

**Evidence — proven and reproduced.** The [ordinary action](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/panel-shell/bot-panel-shell.component.ts#L526-L595) captures `target` and `sid` before awaiting, then writes success/failure directly into `actionReceipt`. The [receipt projection](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/panel-shell/bot-panel-shell.component.ts#L931-L940) omits account/bot identity. The [template](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/panel-shell/bot-panel-shell.component.html#L41-L48) displays it unconditionally below the current bot. By contrast, [safe-flatten preparation](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/panel-shell/bot-panel-shell.component.ts#L598-L643) compares `routeIdentity` before adopting a response.

The [offline characterization](https://github.com/tim1016/learn-ai/blob/research/codex-2427-fleet/review/codex_2427_receipt.cjs) extracts and transpiles the **actual** `onActionRequested` and `successReceipt` methods with the installed TypeScript parser, without booting Angular or copying their algorithm. Synthetic UI signals and a deferred service promise model a shell changing from account-a/bot-a to account-b/bot-b before success arrives. The real method sends exactly one command to **account-a/bot-a**, then displays `receipt-a` and the generic “Bot stopped.” while account-b is current. A no-navigation positive control displays the same receipt under account-a. The test deliberately stubs the already-reviewed outbound fence as satisfied; it does not qualify the Angular router, browser rendering, or HTTP integration. Actual browser reproduction was not performed. Source explicitly models shell route reuse and binding changes in `routeIdentity` at [lines 262–278](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/panel-shell/bot-panel-shell.component.ts#L262-L278).

**Why it matters.** An operator can see a success under the wrong bot after navigation or a rebound lane. The isolated method result and missing response guard establish the race; they do not establish that every navigation preserves the same component instance.

**Recommendation.** Bind ordinary action feedback to the same captured route identity as its command. Preserve completed outcomes in an explicitly named original-target receipt/history, and suppress or clearly identify feedback when the current view differs. Clear stale displayed receipts on target transitions. Retain the existing command-target capture and durable reconciliation identity.

**Confidence. High** in the method behavior; **medium** in real navigation frequency. An actual destruction/remount guarantee for every relevant target transition, or an upstream view ownership guard not present in the inspected shell, would narrow applicability.

## Positive controls and rejected hypotheses

1. **Frozen intent is enforced at multiple boundaries.** [Immutable resource targets and command context](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/fleet/resource-target.ts#L130-L179) carry broker/clerk/account/entity and expected binding generation. [Open-time fencing](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/fleet/open-lane-fence.ts) eagerly freezes the observed lane rather than rebuilding the fence at click. [Envelope validation](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/broker/fleet/routing.py#L692-L766) requires a generation for execution commands and reconciles target/entity/idempotency fields with the route. Service tests exercise wrong provider, wrong account, stale generation, unconfirmed assignment and cross-lane isolation.
2. **An uncertain effect is not replayed as definitely unsent.** [Dispatch](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/broker/fleet/routing.py#L439-L555) marks a durable attempt before delivery and treats post-dispatch identity/transport failure as uncertainty. Same-key in-flight, cancelled and settled attempts do not redispatch in the guarded conformance tests. Routing settlement is monotone and its first upstream receipt immutable. The coordinator receipt is correlation, not execution truth.
3. **The serving agent checks pins before the handler.** [Middleware comparison](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/broker/fleet/agent_identity.py#L124-L169) checks broker/clerk and mutation epoch/generation; the serving role requires an authenticated coordinator forward. Six new [in-process ASGI checks](https://github.com/tim1016/learn-ai/blob/research/codex-2427-fleet/review/codex_2427_identity.py) verify wrong broker/clerk/epoch/generation/token cannot reach a recording handler, and correct identity reaches it exactly once.
4. **Response provenance is verified independently.** [Delivery](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/broker/fleet/delivery.py#L154-L260) verifies echoed identity and per-event stream fields. Missing success echo and echoless redirects do not settle delivered; server failures remain unknown outcomes. Error responses with wholly absent echoes preserve the lane refusal rather than fabricate a success. Actual remote socket transport was not qualified here.
5. **Live data and evidence reads discard stale callbacks.** [The live store](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/lib/bot-panel-live-store.service.ts#L89-L175) increments its local generation, tests it after asynchronous work, and separately fences transaction-detail responses. [The evidence timeline](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/broker/v2-panel/operator-lens/transaction-evidence-timeline.component.ts#L70-L111) resets and checks a request generation. These source checks narrow F1 to an inconsistent ordinary-action feedback path, not a universal cross-account display defect.

[ADR 0062 Decision 5](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/docs/architecture/adrs/0062-broker-clerk-fleet-control-plane.md#L67-L69) states, “Browser selection is never command authority,” and freezes intent from the server resource. That rationale remains valid and supported. No ADR reversal is recommended; apply the same identity discipline to receipt presentation. Configuration-access operations intentionally remain routable on a broken/unbound lane so it can be repaired; their lack of an execution assignment is not counted as a gate bypass.
