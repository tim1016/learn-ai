# Daily return distribution study

**Concept**: Take the minute bars a symbol already has in the data lake, compute each trading day's return three ways (close-to-close, session-only, overnight gap), and histogram the days into fixed-width "baskets" — the empirical distribution of daily returns, the study shape of Fama (1965) §I.B and Mandelbrot (1963). Clicking a basket opens the days inside it, each decomposed across the full 24-hour cycle (overnight gap, pre-market, morning, afternoon, after-hours), plus a minute-candle view of the selected day.

**Reference**: Fama, "The Behavior of Stock-Market Prices" (1965) §I.B and Mandelbrot (1963) for the study shape (histogram of daily changes; fat tails vs the normal). Moment estimators: the adjusted Fisher-Pearson standardized coefficients G1/G2 — the `bias=False` definitions documented at https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.skew.html. Historical VaR/CVaR: McNeil, Frey & Embrechts, *Quantitative Risk Management* (2e) §2.2–2.3 (empirical quantile and tail-expectation estimators). No vendored code was ported; the definitions are standard and the oracle is scipy/numpy.

**Canonical implementation**: `PythonDataService/app/research/return_distribution.py` (all math, pure functions over bars + factor rows), `app/services/return_distribution_service.py` (lake read + orchestration, off the event loop per #1943), `app/routers/return_distribution.py` (`POST /api/research/return-distribution`). Registry rows in `docs/math-sources-of-truth.md` and `docs/architecture/engine-authority-map.md`.

**Validated against**: `PythonDataService/tests/research/test_return_distribution.py` — hand-computed anchors/segments on synthetic extended-hours days (including the 2024-07-03 half-day), factor-file as-of semantics pinned with a dividend-restoration case and a 2:1 split, capture-gap chain resets, log-space identities, bin-edge membership, and a live scipy/numpy oracle for every statistic. LEAN factor lookup parity: `tests/data_lake/test_factor_files.py` (a verbatim port of LEAN's `CorporateFactorProvider.GetScalingFactors` walk, over a 900-day grid, plus a builder round trip across a 2:1 split). Golden fixture `tests/fixtures/golden/return-distribution/RD-001`: 60 real NYSE sessions of deterministic synthetic bars; the committed `output.arrow` is produced by the generator's **independent numpy/scipy oracle** (the canonical module is not on the generator's import path), and `tests/fixtures/test_return_distribution_golden.py` executes the *current* production pipeline over `input.arrow` and requires agreement with both the live oracle and the committed output at `atol=1e-9, rtol=0` — a canonical regression fails against numbers it did not produce. Tolerance note: the oracle (numpy pairwise / scipy) and the canonical module (`math.fsum` loops) evaluate identical closed forms with different summation orders — divergence is ulp-level (~1e-13 at n=60), four orders below the pinned tolerance; bin counts are exact integer equality.

## Return kinds and session segments

| Return | Definition (anchors) | Additivity |
|---|---|---|
| `close_to_close` (default) | previous scheduled RTH close → this session's RTH close | = overnight + session (log-exact) |
| `session` | RTH open → RTH close | = morning + afternoon (**by construction**: `afternoon_log = session_log − morning_log`) |
| `overnight` | previous RTH close → RTH open | the gap component of close-to-close |
| `pre_market` | first extended bar open → RTH open | supplementary; the traded portion of the overnight gap |
| `morning` | RTH open → close of last bar starting before 12:00 ET | |
| `afternoon` | 12:00-ET boundary → scheduled close | half-days close at their scheduled close (13:00 ET), never a 16:00 literal |
| `after_hours` | RTH close → last extended bar close | supplementary |

All returns are computed in **log space** and displayed as simple percent via `expm1`. The log-space identities hold exactly; in displayed percent the same sums hold to second order (geometric compounding: morning 1.2% + afternoon 0.8% ≈ day 2.0%), the standard convention for decomposing a day's move. Segment `None` means the segment genuinely produced no bars (e.g. no pre-market trades), never zero.

Close-to-close and overnight follow **scheduled-session adjacency**: a day returns against the immediately previous NYSE session of the calendar, and only if that session is captured with an RTH close. Across a capture gap the chain **resets** — that day keeps its session return but has no close-to-close/overnight — rather than labeling a multi-session move a daily return (which would contaminate the histogram and every tail statistic). A scheduled session whose day produced no RTH bars likewise cannot serve as the previous close.

Session boundaries come only from `app/lean_sidecar/trading_calendar.py`; the study's own constants are the 12:00 ET morning/afternoon split and the 04:00–20:00 ET extended-hours envelope the lake captures.

## Baskets (bins)

Fixed width (0.5 default, 1.0 option), edges at multiples of the width so **0 is always a bin edge**, inner bins `[lo, hi)` spanning ±5% by default, plus two **open edge bins**: `v < −span` on the left and `v ≥ +span` on the right. Membership is lower-inclusive on inner bins — `v = −5.0` lands in `[−5.0, −4.5)`, `v = +5.0` in the right edge bin — so the union covers ℝ with no overlap. The wild days stay visible by design; clipping them is what the original hand-run study got wrong.

Every response day carries `bin_indices`: its bin per return kind under that response's geometry, stamped by the **same membership function** that tallied the histogram counts — the drill-down selects days by this identity and never re-derives membership client-side.

## Statistics

All in simple-percent units, on each kind's series: N, mean, sample std (ddof=1), annualized vol = σ·√252, skew G1, excess kurtosis G2 (Fisher), historical VaR-95 = linear-interpolated 5th percentile (numpy `method="linear"`), CVaR-95 = mean of the values at or below VaR-95, best/worst day with dates. The bell-curve overlay is the expected count per bin under `Normal(mean, std)` fitted to the same series — `N·(Φ(hi) − Φ(lo))`, Φ via `erf`, identical to `lean_statistics._normal_cdf`.

The estimators are **total over valid input**: a flat series has σ = 0, skew/kurtosis `null`, and a zero overlay — never a division-by-zero; a series of n < 4 has `null` skew/kurtosis and (for n < 2) `null` σ. `null` is "undefined for this sample", never zero.

## Corporate-action adjustment

The study reads the **raw** lake root (deepest coverage) and multiplies each day's anchors by the lake's own LEAN factor-file `price_factor · split_factor` as of that date. Parsing and the as-of lookup are canonical in `app/data_lake/factor_files.py::factor_multiplier_as_of`, which implements LEAN's `CorporateFactorProvider.GetScalingFactors` semantics: the **earliest row dated on or after** the bar wins (a row dated D covers data back through D; D's successor uses the next row; data before the first row uses the first row's cumulative factors; data after the last row is unadjusted). Splits and dividends are therefore both removed from the return series, with event-day continuity parity-tested against a verbatim port of LEAN's walk. When no factor file exists the response says `adjustment: "raw"` with a warning — unadjusted series can show corporate-action days as outlier moves. Lake prices are deci-cent quantized (1e-4 grid), the same precision seam the chart documents; at 0.5% bin width this is four orders below decision-relevant scale.

## On-demand capture

The study is capture-on-demand: it always *computes* over lake bytes, but when the read window — **14-day lead-in included**, so the first in-window session keeps its previous close — has completed sessions the lake does not hold, they are delta-fetched first through `materialize_symbol_history` (`app/data_lake/run_materialization.py`): the shared async materialization seam, which asks for minute trade bars **plus the factor and map files** (so a newly captured symbol gets split+dividend adjustment from its first request), stays off the daily rollup, and — unlike a bare `ensure_data` call — waits out a concurrent request that owns the catalog claim and is bounded wall-clock by its `fetch_timeout_seconds` (600 s here). The capture span is the completed-session prefix of the read window (clamped before the still-forming session — the same calendar split the chart composer uses). Catalog claims coalesce concurrent studies of the same cold symbol into one fetch; provider, catalog, and timeout failures are contained into the response's `meta.capture` receipt whose `status` is a closed contract (`not_attempted` / `skipped` / `complete` / `partial` / `failed`) rather than failing the request — the study then computes over whatever landed, and the frontend renders every state distinctly (a `failed` capture is never presented as "already up to date"). A capture that still leaves the window empty (unknown ticker, entitlement or auth failure, catalog down) is a typed `NOT_CAPTURED` 404 whose `capture_note` carries the reason; a symbol the lake can never address (path-unsafe per the writer's alphabet) is the same typed error without a capture attempt.

## Coverage semantics

The service reads a 14-calendar-day lead-in before `from_date` so the window's first session has a previous close to return against; the on-demand probe checks that lead-in too, so a lake holding the requested dates but not the fortnight before them is still captured. The capture boundary splits sessions under the **extended** policy — this study consumes after-hours bars, so a session only counts as immutable capture history once its 20:00-ET tape has finished. Error mapping keeps caller errors and operational failures apart: unusable study geometry (including a bin count beyond 100 per side) is a typed 400/422, while a malformed factor file or corrupt lake zip propagates as an operational 500 rather than masquerading as an invalid request. `coverage` reports requested (scheduled) vs returned sessions, missing sessions (scheduled but not captured even after the on-demand capture), and excluded sessions (captured but without RTH bars); days whose previous scheduled session is missing keep `null` close-to-close/overnight with a warning rather than spanning the gap. Fewer than 30 captured sessions is a typed `INSUFFICIENT_COVERAGE` 400. First-time captures of a two-year window can take tens of seconds; the frontend loading state says so.

## Day-candles drill-down

The candle pane (`POST /api/research/return-distribution/day-candles`) reads the selected day's extended-session minute bars from the **same raw lake root** and scales prices by the **same LEAN factor-file multiplier** the study applied to that day's anchors (one trading date → one multiplier; volume unscaled) — so the pane's price basis is the return being inspected by construction, rather than the provider feed's split-only adjustment. A day the lake does not hold is a typed `DAY_NOT_CAPTURED` 404; there is no capture-on-demand on this path because the day was named by a study response that already captured it.

## Wire conventions

The request carries the window as `from_ms_utc` / `to_ms_utc` (int64 ms UTC) — resolved to inclusive UTC calendar dates inside Python through `resolve_request_dates`, the same authority and anchoring the Data Lab store commits (start = UTC midnight of the first trading date, end = the day's final UTC instant) — so no date string ever travels and the workspace's numeric window passes through verbatim. Every temporal value on the response is int64 ms UTC (session-anchored opens); per-day dates are derived at render time.
