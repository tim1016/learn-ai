# Strategy validation and backtesting verdict integrity — independent review

Ticket: [Strategy validation and backtesting verdict integrity](https://github.com/tim1016/learn-ai/issues/2416). Parent: [Independent review: bot trading engine & backtesting](https://github.com/tim1016/learn-ai/issues/2413).

Baseline: `10b5f31b529c8507bd19bb24015f3d85fa9aba43`. Every source path and line below refers to this revision. Research branch: `research/codex-2416-validation`. This is a bounded first pass of all five Strategy Tools surfaces, not a certification of all strategies or production state. No fixes were made.

Outcome: **one Critical and two High findings**. A common metric silently drops the first evaluated session, changing a walk-forward verdict in a synthetic counterexample. Paired execution can replace marked portfolio risk with closed-trade pseudo-equity under the same headline metrics. Strategy Spec bypasses lake materialization and can report a successful empty-data run.

## Finding V1 — The first evaluated session is omitted from return statistics and can reverse a walk-forward verdict

- **Claim:** Daily resampling retains the first day's closing equity, discards that day's opening equity, and computes differences only between remaining closes. The first evaluation-day return is therefore absent from Sharpe, Sortino, annual volatility and PSR, including every fold's independently reset test window.
- **Goal:** Correctness; trading intelligence.
- **Severity:** **Critical** under this review's definition of a silently wrong validation verdict. This is not a claim that the grade authorizes an order.
- **Evidence — proven source:** [`statistics.py:384-398`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/engine/results/statistics.py#L384) collapses each ET date to its last point and starts return differences at index 1. Its equity branch applies those returns at `:572-579`; `summarize` repeats the same vector for volatility/PSR at `:663-675,704`. `initial_cash` is available but unused as that first return's denominator. The engine adds evaluation snapshots only after processing bars (`app/engine/engine.py:494`), so no preceding-day anchor repairs this upstream. Adding an opening snapshot on the same date also does not repair it: resampling overwrites it.
- **Evidence — proven reachability:** [`engine_backtest_service.py:965-983`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/services/engine_backtest_service.py#L965) passes the evaluated curve directly. `grid_search/engine_adapter.py:53-68` copies `statistics.sharpe_ratio`; `walk_forward_study/service.py:232-243` copies the winner's test Sharpe into fold evidence. [`verdict.py:124-133`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/research/walk_forward_study/verdict.py#L124) uses its sign and ratio. The frontend renders the returned verdict verbatim (`walk-forward-study-result.component.html:41-50`).
- **Evidence — reproduced:** `review/codex_2416_validation.py::first_session_omission` supplies opening equity plus five session closes for returns `[-20%, +1%, +2%, -1%, +1%]` and five consistent closed-trade returns. Net return is **−17.5922416%**. Production statistics report **Sharpe +9.461834694681244**; the same sample including its initial return gives **−5.776596936341366**. Passing the produced scalar/count to the real one-fold verdict with training Sharpe 1 and minimum five trades produces **“still worked”**; correcting only the omitted return produces **“stopped working.”** This exercises the production statistic and verdict functions, not a persisted study or broker.
- **Why it matters:** A loss at a fold boundary is systematically removed from the risk-adjusted test evidence while still present in terminal P&L. Grid ranking can prefer the wrong candidate and a short test fold can appear to retain a positive edge after losing money. Dropping an initial gain biases the opposite direction as well.
- **Recommendation:** Define a single evaluated return-vector contract that explicitly includes opening capital and the first session's P&L, and feed every daily risk/confidence consumer from it. Validate the compounding identity against terminal equity, including short windows and each warmup→evaluation reset. Correcting the scalar should change verdicts naturally; do not special-case a headline label.
- **Confidence:** High. Source and function reproduction agree. A proven caller contract that intentionally excludes the first day and labels the evaluated window accordingly would change the judgment; the examined consumers advertise the whole requested evaluation window instead.

## Finding V2 — Paired Strategy Lab runs replace marked portfolio risk with closed-trade pseudo-equity

- **Claim:** Selecting both engines switches the Python result's platform statistics to a reconstructed all-in closed-trade curve, dropping intratrade drawdown and changing the statistical sample, while the primary result still exposes those fields as portfolio Sharpe/Sortino/Max drawdown.
- **Goal:** Correctness; trading intelligence; architecture.
- **Severity:** **High** — realistically understated portfolio risk and incomparable results under the same UI labels. No claim is made that this changes broker state or that the reproduced three-trade example produces a complete 17-input grade.
- **Existing rationale, quoted before challenge:** `docs/references/reconciliations/engine-lab-runs-75-76-statistics-validation-plan.md:171-175` states: “Both sides grade the common closed-trade ledger through the same platform statistics implementation. This closes the readiness-input mismatch.” The immediate implementation rationale at `engine_backtest_service.py:971-973` is that LEAN's native chart is sparse. Equal inputs are a valid parity need. A closed-trade curve nevertheless cannot establish actual intratrade portfolio risk; matching two restricted projections does not supply the observations they both omit. This recommendation retains the parity projection and separates its purpose rather than asking to use a sparse chart as a portfolio ledger.
- **Evidence — proven source and reachability:** [`strategy-lab-runner.service.ts:292-305`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/strategy-lab/strategy-lab-runner.service.ts#L292) sends `us-equity-raw-ibkr-v1` when `engine === both`. [`engine_backtest_service.py:971-983`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/services/engine_backtest_service.py#L971) deliberately sets the statistic curve to `None`. `statistics.py:169-183,588-606` compounds trade percentage returns and computes its drawdown in place of marked-equity drawdown. The same `stats` feed `compute_run_verdict` at `engine_backtest_service.py:1015-1028`. [`results-summary.component.html:15-19`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/strategy-lab/results-summary/results-summary.component.html#L15) uses unchanged headline labels. Metric help and native evidence exist, but do not prevent replacing the primary numeric series.
- **Evidence — reproduced:** `compatibility_drawdown` holds three closed returns `[+1%, −1%, +2%]`, starting capital and final equity `$101,989.80` constant, with an intratrade dip to `$50,000`. With the marked curve, production `summarize` reports **50% max drawdown**. With the compatibility call's `equity_curve=None`, it reports **1%**. The missing information is real economic exposure even when both engines' closed trades agree perfectly.
- **Why it matters:** Comparing engines should increase confidence in the same research result, not alter which risk was measured. The all-in reconstruction also encodes position allocation assumptions explicitly acknowledged as inaccurate for other allocations in `statistics.py:170-175`. Cross-engine agreement can conceal omitted risk if the common projection is reused as the primary grade input.
- **Recommendation:** Keep parity metrics as an explicitly typed, separately named closed-trade projection. Portfolio risk and confidence should retain their marked, cost-aware return basis; when a peer cannot supply an equivalent ledger, report that comparison as unavailable. Persist metric basis/sample identity with each value so an execution-mode change cannot silently substitute a different estimand in the same headline or grade.
- **Confidence:** High for the substitution and 50%→1% reproduction; medium for how often current portfolios are materially affected. No production run was inspected. An enforced restriction that prohibits using those paired values as portfolio metrics, visible in both contract and primary presentation, would reduce severity.

## Finding V3 — Strategy Spec can silently succeed on an empty or incomplete legacy data tree

- **Claim:** Strategy Spec constructs a legacy environment-root reader directly, without lake policy resolution or coverage/receipt admission, and reports success if the engine completes without an exception even when it consumed zero bars.
- **Goal:** Correctness; architecture; trading intelligence.
- **Severity:** **High** — a missing-data failure can be indistinguishable from a flat/no-signal strategy result, and partial histories can produce plausible incomplete results without a coverage error. Empty-data behavior is reproduced; partial-history impact follows the source path and is not presented as a separately executed portfolio example.
- **Evidence — proven source:** [`spec_strategy.py:113-132`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/routers/spec_strategy.py#L113) resolves `LEAN_DATA_ROOT`/`LEAN_DATA_CACHE` itself. In contrast, `app/engine/data/policy_store.py:57-85` resolves the selected lake adjustment root. [`lean_format.py:263-274,309-323`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/engine/data/lean_format.py#L263) simply skips dates without ZIPs. `spec_strategy.py:328-345` unconditionally authors `success=True` after a non-throwing engine call, with no bar count, coverage or manifest field in `SpecBacktestResponse` (`:83-101`). The comparison engine-service path explicitly rejects an empty curve at `engine_backtest_service.py:941-944`.
- **Evidence — reproduced at real route boundary:** `spec_empty_source` loads the committed SMA spec, directs the real default factory to a new empty temporary directory, and calls `run_spec_backtest` for 2025-01-06 through 2025-01-10. Result: **`success=true`, `error=null`, 0 trades, final equity `$100,000`, no log lines**. No dependency was replaced with a fake success function. [`spec-strategy-runner.component.html:490-503`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/spec-strategy-runner/spec-strategy-runner.component.html#L490) renders this as the ordinary results panel; `spec-strategy.service.ts:89-94` surfaces an error only for an unsuccessful result.
- **Why it matters:** Instrument-card lake coverage does not prove the separate legacy root contains the same data. Backfills and adjustment policy can therefore differ from the bytes the spec actually reads. An all-zero result can steer strategy editing while hiding the actual issue: the run never observed the market.
- **Recommendation:** Satisfy the existing lake authority through the shared run-materialization boundary: resolve adjustment/session policy, establish coverage and data identity, and make partial acceptance explicit. Reject empty evaluation windows. Return consumed-window evidence with the spec result so zero trades can be distinguished from zero observations.
- **Decision relationship:** This supports, rather than reverses, ADR 0049's lake authority and Decision 3a assigning partial-data admission to the run-materialization seam. It does not require adopting a universal refuse-all-partial policy.
- **Confidence:** High for the demonstrated empty-tree result and legacy-root divergence; medium for production frequency because deployment environment and historical artifacts were intentionally not read.

## Controls satisfied and counter-evidence

- **Training/test separation is real at the selection seam.** The test sweep is run broadly, but `walk_forward_study/service.py:225-233` selects the training winner's test row and explicitly stamps the other rows exploratory. The UI reiterates that distinction (`walk-forward-study-result.component.html:1-5,60-64`). No test-window leader substitution was found.
- **Verdict incompleteness is explicit.** Failed folds, no positive training denominators, inadequate defined-fold coverage and insufficient trades gate the walk-forward verdict (`verdict.py:117-125`). Grid rank excludes failed, zero-trade, nonfinite and below-minimum cells (`sweep/ranking.py:57-58`). The fold planner refuses a non-divisible tail and creates contiguous non-overlapping test intervals (`walk_forward_study/folds.py:88-126`). All 27 selected existing fold, verdict and ranking tests passed.
- **Sweeps bind execution to receipts.** `grid_search/engine_adapter.py:43-47,87-95` disables autofetch and supplies the frozen data manifest to the same engine service as Strategy Lab. Grid preflight checks parameter validity, workload, resolution, warmup and availability (`grid_search/service.py:190-240`). The study freezes a whole-range snapshot and code identity (`walk_forward_study/service.py:94-114`). These are stronger controls than the Spec path.
- **A grade does not become permission to trade.** Missing required metrics suppress the composite/grade/action (`run_verdict_service.py:181-210`); the frontend calls it a fixed 17-input backtest evidence summary and states it does not authorize trading (`evidence-grade.component.html:35`). Strategy validation checks human flags and current artifact binding (`strategy_validation_admission.py:99-144`), including a specifically documented durable override distinction. No bypass of that policy is claimed here.
- **A suspected future-price sizing leak was rejected.** `StrategyContext.register_consolidator` resets the sizing reference to the emitted bar before invoking strategy code (`app/engine/strategy/base.py:168-176`). Its separate stale post-handler mark consequence was forwarded to the backtest/live-seam investigator to avoid duplicate findings.
- **Fill and cost controls are present, with limitations.** Grid requests carry fill mode, per-order commission and per-share slippage; the fill model applies slippage against trade direction (`fill_model.py:147-151`). Signal-close mode remains the default in Strategy Lab, Spec and shared sweep editor. The code explicitly describes signal-close as reference-bookkeeping replication and next-open as the realism mode. This pass did not establish a new causality failure beyond the issues above; realism defaults and selection-adjusted statistical confidence warrant a focused follow-up.

## Sharp follow-ups and owner questions

1. **Does a strategy's reported statistical confidence remain calibrated after search and repeated study inspection?** Trace the actual experiment/trial identity across Grid Search → Walk-Forward → Strategy Lab; test repeated selection on synthetic null strategies, serial dependence and arbitrary window tuning. Determine whether missing trial history is disclosed or silently treated as one trial. The existing PSR consumes only one return vector (`statistics.py:294-324`); no broad claim that the whole product lacks a correction was made in this pass.
2. **Do supported fill modes preserve causal fills and realistic cost sensitivity across the default registry strategies?** Specify gap/session-boundary fixtures, order creation vs bar availability, signal-close/reference mode eligibility, and robustness under nonzero slippage. This should follow the directly reachable paths only; no live execution or vendor data is required.
3. **Owner judgment, if a product choice is needed:** Should compatibility comparison ever replace the primary economic-risk grade, or should it remain a separately labelled parity projection? Recommended answer: keep portfolio risk on its marked basis and display parity evidence separately, even when a peer cannot provide a complete comparable ledger. Evidence is V2; the historical common-input rationale is preserved above. No owner decision has been simulated or marked resolved.
