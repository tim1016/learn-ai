## S1 — Selection-unadjusted PSR receives an unqualified “Near-certain” note

**Claim.** Strategy Lab's supplementary confidence label can imply certainty about an edge after a researcher selected the best of many candidates, although the statistic and verdict input represent only the selected return vector. This is a bounded reporting/scope defect, not evidence that PSR itself is incorrectly implemented or that the entire grade authorizes trading.

**Goal.** A researcher should be able to distinguish conditional, single-vector confidence from confidence adjusted for the process that selected the strategy.

**Severity. Medium.** The wording is overconfident at its point of use and contributes a positive subscore. Its effect is bounded by the main grade's explicit frozen-policy and independent-validation limits and by the more careful analytical manual. No direct trading authorization or new falsely passing causal holdout was reproduced.

**Evidence — proven in source.**

- [`statistics.py:292-321`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/engine/results/statistics.py#L292-L321) computes PSR against zero from one vector's count, Sharpe, skew and kurtosis. It receives neither selection history nor trial count.
- [`RunVerdictInput:87-93`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/schemas/run_verdict.py#L87-L93) has six fields, none describing how the candidate was chosen. The statistical-confidence dimension asks whether the edge is trustworthy or overfitting noise at [`run_verdict_service.py:390-410`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/services/run_verdict_service.py#L390-L410), and PSR ≥ 0.99 scores 18/20 with the note at [`:789-801`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/services/run_verdict_service.py#L789-L801): “Near-certain - verify sample size isn't inflated.” Sample count is not the only assumption that selection violates.
- This is a real consumer, not dead backend prose: [`results-sidebar.component.ts:33-40,58-66`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/strategy-lab/results-sidebar/results-sidebar.component.ts#L33-L66) includes PSR and maps its score to the positive band; [`results-sidebar.component.html:7-13`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/strategy-lab/results-sidebar/results-sidebar.component.html#L7-L13) displays its percentage and uses that note as the tooltip.

**Evidence — reproduced.** [`review/codex_2421_selection.py`](../../review/codex_2421_selection.py) generates 1,000 independent 252-observation Gaussian return vectors with generating mean zero, seed 2421, selects the maximum observed Sharpe, and calls the production PSR and subscore functions. Winner index 598 has annualized Sharpe **3.212909494790785**, PSR **0.9991312578495453**, score **18**, and the **“Near-certain”** note. The artifact asserts the verdict input has no trial/selection field. It supplies complete vectors directly, avoiding the separate first-session omission. This single deterministic demonstration is not a false-positive-rate estimate, an engine strategy backtest, or proof that this winner subsequently loses. The ordinary skepticism heuristic would flag Sharpe > 3; that independent flag does not alter this PSR label and is not a multiple-testing adjustment.

**Why it matters.** Comparing many candidates changes the interpretation of an extreme selected result even when observation count is honest. The primary paper distinguishes PSR's return-distribution/sample correction from DSR's additional selection correction; repeated holdouts also do not remove the multiplicity problem. See Bailey and López de Prado, [*The Deflated Sharpe Ratio* (2014), pp. 6, 8–9, equations 1–2](https://www.davidhbailey.com/dhbpapers/deflated-sharpe.pdf). This citation supports the statistical interpretation, not a claim that DSR must be the repository's chosen policy.

**Counterevidence and rationale.** The function intentionally documents a platform-canonical zero-benchmark PSR distinct from LEAN's interest-rate-aware PSR. That contract can remain useful. The UI says the grade is a frozen 17-input policy and does not authorize trading, and shows a next validation step ([`evidence-grade.component.html:18,31-35`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/strategy-lab/evidence-grade/evidence-grade.component.html#L18-L35)). The analytical catalog already states the probability is conditional on estimator/sample assumptions and cautions that observation count does not measure independence ([`analytical_metric_catalog_results_entries.py:57-59,87-89`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/PythonDataService/app/research/documentation/analytical_metric_catalog_results_entries.py#L57-L89)). No ADR is challenged, and the demonstration does not invalidate the frozen score merely because it is a heuristic.

**Recommendation.** Label PSR at the visible metric/tooltip as conditional on the supplied sample and unadjusted for strategy selection; remove “Near-certain.” Show selection adjustment as unavailable unless a defensible trial/campaign record exists. A future choice to grade a selection-adjusted measure should be an explicit versioned policy decision with fixtures, not an undocumented substitution into the current PSR contract. Retain the existing independent-validation action.

**Confidence. High** in the source behavior and deterministic demonstration; **moderate** in the user-interpretation severity. A point-of-use selection caveat, or a verified upstream contract that prevents selected candidates reaching this scorer, would reduce or resolve this finding. Merely knowing the selected vector's trade count would not.

## Remaining limitation and sharply bounded follow-up

The grid-to-study link copies the same window, parameters and costs. [`walk-forward-study-page.component.ts:87-93`](https://github.com/tim1016/learn-ai/blob/10b5f31b529c8507bd19bb24015f3d85fa9aba43/Frontend/src/app/components/walk-forward-study/walk-forward-study-page.component.ts#L87-L93) keeps only `detail.request`; source search ID is transient display text. `StudySpec` has no parent search/campaign or previously inspected-window field. Thus a user may repeatedly inspect that window or alter hypotheses before launching a study, and the study cannot establish that it is an untouched holdout. **This is recorded as a limitation, not a second defect:** current copy narrowly says the test is out of sample for settings chosen inside that fold. It does not promise the researcher had never examined those dates.

Owner question: should a future study promise an independent discovery/confirmation split, or remain explicitly a descriptive rolling re-selection experiment? If stronger confirmation is desired, a bounded next design investigation should specify campaign identity, source-search ancestry, prior window exposure, all attempted hypotheses (including failures), and the selected correction/holdout policy. It should not infer statistical independence merely from a new study ID or raw cell count. No new broad code audit is required to answer the current ticket.
