**Question:** Where does the live Alpaca submit → custody path fail open rather than closed?

**Commit read:** [`e7325d2ff0a122ffde3418cac94aa2f872f10ffa`](https://github.com/tim1016/learn-ai/tree/e7325d2ff0a122ffde3418cac94aa2f872f10ffa)

**Date:** 2026-08-17

**Answer:** The activated SQLite path is capture-first and handles ordinary submit timeouts, caller cancellation, mirror failure, and missing production wiring fail-closed, but it has four conditional fail-open seams: an `accepted` ENTER can survive a crash and an exact-lookup error without becoming an admission-blocking uncertainty (full reconciliation records the attempt as `STILL_UNKNOWN`, but does not mutate the accepted effect or create a blocking uncertainty/hold); unexpected reconciliation failures can release the in-process admission fence without authoring stale/unknown evidence; the low-reachability incomplete-ENTER branch with no captured order calls the work “resolved failure” without closing it or raising a hold; and a trade-update capture or parse failure discards custody evidence while leaving the execution channel healthy. A fifth confirmed seam exists on the still-selectable legacy JSONL authority: bot effects call `_submit_leg` directly and bypass the dual-channel submit gate that protects `submit_for_instance`. These are code-path findings, not claims that each compound fault has occurred on the paper account.

## Second-pass refutation details for confirmed findings

### 1. Legacy health-gate bypass

The strongest possible refutation was that `_submit_leg` might be safe because its caller had already synchronized a `STREAM_HEALTH_HOLD`. It had not: `_resolve_enter` reads only the previously durable hold, and the hold is authored lazily by `_submit_batch` when that different call path evaluates `stream_health_refusal`. Production does inject both health providers into the legacy Clerk, but injection alone is not enforcement. A disconnected execution stream can therefore coexist with no prior hold and a bot effect reaching the broker. Confidence: **high** on mechanism and reachability for unactivated/legacy-selected accounts; **not applicable** to the activated SQLite account.

### 2. SQLite accepted-operation gap

The surviving sequence is narrow but deterministic: `ENTER_ACCEPTED` commits; the process dies before broker contact; startup obtains clean open-order/position snapshots; exact client-id lookup alone raises `BrokerError`; `resolve_order_submission` returns; full reconciliation appends a durable `RECONCILIATION_ATTEMPTED`/`STILL_UNKNOWN` receipt whose `operation_state` remains `accepted`; final broker inventory remains clean; startup installs the writer; custody projection omits the still-`accepted` order because it selects only `unknown`; and admission has no nonterminal-ENTER fence. Thus the defect is not absence of a durable diagnostic receipt—it is that the receipt neither changes authoritative effect/order state nor creates an admission-authoritative uncertainty/hold. The schema permits multiple nonterminal ENTER effects (uniqueness is by idempotency key, not strategy), and an existing test deliberately constructs two preaccepted effects ([`test_enter.py:1206-1227`](https://github.com/tim1016/learn-ai/blob/e7325d2ff0a122ffde3418cac94aa2f872f10ffa/PythonDataService/tests/broker/alpaca/clerk/sqlite/test_enter.py#L1206-L1227)). Ordinary submit timeouts do not take this path because they first fold durable uncertainty. Confidence: **high** on code behavior, **moderate** on compound-fault likelihood.

### 3. Healthy socket with rejected fill evidence

The frame handler correctly refuses to derive state without capture/parse proof, but the refusal is local to that frame. It does not mark the socket disconnected, raise to the reconnect loop, raise a hold, or set an evidence-quality watermark. The connected-only health model also has no last-valid-frame freshness budget. The next ENTER snapshots only market-feed health plus socket connection. The gap is nominally bounded by the next successful periodic reconciliation (scheduled at 15-second intervals), not by a synchronous gate; repeated reconciliation failures can leave it unbounded. Confidence: **high** for capture failure; **moderate** that any particular malformed frame represents an economic event.

### 4. Reconciliation exception paths

Normalized snapshot failure is not a finding: `_read_account_snapshot` catches `BrokerError`, durably raises `BROKER_SNAPSHOT_STALE`, and returns stale ([`reconcile.py:447-473`](https://github.com/tim1016/learn-ai/blob/e7325d2ff0a122ffde3418cac94aa2f872f10ffa/PythonDataService/app/broker/alpaca/clerk/sqlite/reconcile.py#L447-L473)). Mirror-finalization and lease failures also prevent future writes. The first confirmed remainder is an unexpected adapter/programming exception caught only by the sweep after `finally` releases the gate. The second is narrower: only an already-incomplete ENTER whose effect has no captured order can both take the `RESOLVED_FAILURE` catch and lack another admission fence. Effect+order normally fold in one transaction, so valid-state reachability is low; malformed EXIT does not qualify because `active_exit_for_strategy` still blocks that strategy's new exposure. Confidence: **high** on branch semantics, **moderate/low** respectively on production occurrence.

## Confidence and limits

Overall confidence is **high on control flow and verdict classification**, **moderate on operational likelihood**. The sweep was static at the pinned SHA; no paper-broker fault was injected and no code was changed. It covered the current activated SQLite route and the selector-reachable legacy Alpaca route, including decision receipt, effect ownership, admission, capture-before-contact, broker error mapping, acknowledgement, websocket fill folding, startup/reconnect/periodic reconciliation, shutdown, mirror fencing, and start admission. It did not re-audit manual-order custody or EXIT/cancel economics beyond checking timeout/cancellation classification, and it did not treat deprecated IBKR internals as Alpaca evidence. The incidental `docs/doc-authority.md` label that still calls ADR 0035 “proposed” conflicts with the ADR's accepted status; this audit follows the ADR and does not correct that separate documentation defect.
