- **Ticket:** [Clean-up — Alpaca clerk custody: store plumbing](https://github.com/tim1016/learn-ai/issues/3149), a module ticket of [Map — Robustness and cleanliness](https://github.com/tim1016/learn-ai/issues/3146).
- **Read at:** `origin/master` `862b50d3` (2026-10-13 21:17 CDT). No open PR touched this scope.
- **Scope:** 59 Python files — 34 in `PythonDataService/app/broker/alpaca/clerk/sqlite/` (20,259 lines) and 25 test files (13,838 lines). The file list is in the ticket body.
- **Depth:** all seven lenses.
- **Method:** the driver ran the baseline, the static scans and a name-based reachability pass over all 1,122 units, then split the read by file family across eight delegated readers (A–H). Every row below says how it was checked: **repro** (the driver re-ran a reproduction), **read** (the driver read the lines), or **reader** (reported by a delegated reader with its own repro; not re-run). Nothing was run against a live store.

## Verdict

**Two P1s, filed at once: [#3160](https://github.com/tim1016/learn-ai/issues/3160) and [#3161](https://github.com/tim1016/learn-ai/issues/3161). A small delete-only cut PR: [#3162](https://github.com/tim1016/learn-ai/pull/3162).**

- **#3160 (F1).** The intake fence's poison gate is checked once, before the wait for the lock. A task already queued when the fence is poisoned is admitted afterwards, while the abandoned fold's worker may still be writing. Only later arrivals are refused. Reproduced.
- **#3161 (F2).** `open()` accepts a `clerk.db` that is behind its mirror (rows the mirror finalized are missing from the database). The next append reuses a sequence the mirror already finalized; only the following open fails. The supported restore path refuses this; the boot path does not. Reproduced three times, by two readers and the driver. The trigger is an out-of-band file rollback, so the owner may rate it P2.
- **Thirty-odd P2, robustness and test-gap findings** (F3–F41), nine of them reproduced by the driver. The most consequential: a manual-custody operation in the newest 50 makes the account snapshot return 500 (F3), an operation detail silently loses every event after the 100th (F4), and a cancelled send whose claim is gone surfaces as a claim error instead of a cancellation (F5).
- **The cut** removes the package-level export surface nothing imports, one dead read chain (`unfoldable_broker_orders_active_since`), two dead methods and two unused test fixtures, with the tests that existed only for them. About 200 lines deleted, no behavior change.
- **Everything the earlier kill list ([#2701](https://github.com/tim1016/learn-ai/issues/2701)) named in this scope is gone from master.** No symbol in the 34 files is unreachable by name except eight test seams (five already ruled "kept"; the other three are in the candidates table).

## Limits of this read

- **Reader reach.** `runtime.py` (3,849 lines) was read by two readers in halves (A: L1-1950, B: L1900-end); readers did not read the other 97 files of the directory except at call sites. Reader B's coverage set did not include all of `tests/services` or `tests/broker/v2panel`, so a line called uncovered could be hit outside it.
- **No live store was opened.** Every census above is a proposal. Timings in F10 are synthetic, in-memory, with hashes and FKs bypassed; they show shape, not live numbers.
- **Coverage is line, not branch.** Index and column findings (C3–C6) rest on static scans plus `EXPLAIN` against an empty in-memory DB.
- **Reachability is by name.** A common name can hide a dead symbol behind an unrelated caller, which biases toward keeping. Dynamic dispatch was checked for string keys and `getattr` only.
- **Postgres-gated tests:** none are in this scope.
- **WAL growth, `_write_lock` held across two fsyncs and a commit, and O(N) `open`/`verify_database` memory** were noted by reader F and not measured.
