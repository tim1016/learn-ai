# Kill list: dead code in the rest of the Frontend (#2709)

Part of map #2700. Read at **`87b8e261`** (`origin/master`, the same SHA the map was charted at).

**Area.** `Frontend/src/app/` except the broker surfaces (`components/broker/`, `components/brokers/`, `fleet/`, `shell/`, which belong to #2708), plus the Frontend-level config that only this code reads: `src/environments/`, `src/testing/`, `package.json` dependencies, and `src/test-setup.ts`. All paths below are relative to `Frontend/src/app/` unless they start with `Frontend/` or another top-level directory.

## How this was judged

1. **File reachability.** A throwaway TypeScript compiler-API script (it used the main checkout's `node_modules/typescript` read-only and was never added to the repo) built the import graph of `Frontend/src`. The graph has static imports, re-exports, and every dynamic `import()`, so the route tables `app.routes.ts`, `data-lab.routes.ts` and `research-lab.routes.ts` count as callers. A non-spec file that `src/main.ts` cannot reach is dead. Specs, `src/testing/` and `*/testing/` helpers are never counted as callers.
2. **Symbol liveness, below file level.** Inside reachable files, each top-level declaration and each class member is a unit. A unit stays live only if a live unit refers to it, and the script repeats the check until nothing changes, so a method called only by another dead method dies too. To count as a reference, a symbol has to resolve through the type checker, which follows `inject()`-typed fields. A member also stays live if its name appears as a word anywhere in any non-spec template (`.html`, inline `template:` or `host:`). That check errs toward keeping things. Lifecycle hooks, `override`s, interface hooks (`transform`, `canActivate`, …) and fields whose initializer runs `effect()` or `subscribe()` are treated as roots.
3. **Rendered-but-unused check.** Every reachable `@Component`, `@Pipe` and `@Directive` was checked for its selector or pipe name in a live template, or its class in a route or other non-`imports:` reference. All of them passed, so no component is imported without being rendered.
4. **Repo-wide caller search.** Every candidate was grepped across all git-tracked files: `PythonDataService/`, `Backend/`, `scripts/`, `.github/`, compose and deploy files, `docs/`, and `Frontend/scripts`, `tests` and `eslint-rules`. No candidate is dispatched by name from outside the Frontend. Hits in docs and scripts are listed under hazards.
5. **Routes.** Every route in the three route tables was checked for an inbound link (`shell/app-menu.ts`, `routerLink`, or an `href` in templates and TS). Six pages are reachable only by typing their URL. They are kept separate as Tier B below.

### Q1, a rule-level question for the map

**Does a page that still has a route, but no link anywhere in the app, count as reachable?**

1. **No, it is dead (recommended).** A page that was taken off the menu on purpose, and is linked from nowhere, is a retired UI entry. B1 to B6 go, along with their specs and the Backend or Python callers they orphan (see P2).
2. **Yes, it is live.** A typed URL or a bookmark is a real entry point, so B1 to B6 stay, and only Tier A is cut.
3. **Case by case.** Cut demos and sandboxes (B3, B4, B5) and the stale doc copy (B6). Keep the retired features (B1 portfolio, B2 tracked instruments) until the owner retires them by name.

## Not reviewed
