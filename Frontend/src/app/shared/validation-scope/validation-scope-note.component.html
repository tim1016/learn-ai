and what it deliberately does not What LEAN validation covers

Platform figures come from the Python engine — the production engine for backtests, sweeps and studies. The vendored LEAN reference is used to validate that engine, never to run alongside it. LEAN-native values, where a panel shows them, are the reference's own calculations, reproduced independently in Python for comparison.

Validation is summary-level, by design. The engine is checked against LEAN on summary statistics, the closed-trade ledger and global run characteristics (trade count, fees, final equity). Those comparisons are pinned by golden fixtures and parity verdicts on Strategy Lab run evidence. Individual minute bars are never validated one by one — a two-year minute run holds roughly 200,000 of them, and a bar-by-bar comparison would re-prove the same math per bar against a reference chart that samples the equity path far more coarsely than the engine's minute resolution.

Minute detail still exists where a figure is defined on it. Max drawdown is the sharpest example: an intraday dip that recovers by the close is real drawdown here. The Python engine computes it from the minute equity path; the LEAN comparison stays at summary level. A platform drawdown deeper than a LEAN dashboard's is expected, not a defect.

Sweep surfaces — Grid Search, Walk-Forward Study and the Recency Chart — run the Python engine only. LEAN parity verdicts live on Strategy Lab run evidence.
